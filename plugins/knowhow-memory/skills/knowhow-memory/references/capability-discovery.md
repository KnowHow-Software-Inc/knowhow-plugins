# Capability discovery

Use this when the user asks who can help, or a missing answer blocks progress.
Tell the user that you can look for people with relevant contributions.

## Investigate

Make the question specific. A weak search does not show that the company has
no answer. A current `gap` memory can show that someone already asked, and
whom.

Use `find_people`, then read the memories that connect each person to the
question. Also search other sources that the host can reach, such as
repository documents, Git history, messages and shared files. Follow concrete
evidence; do not inspect every connected system.

## Propose whom to ask

Name the contribution that connects each candidate to the question: an
authored procedure, a related change, an explained exception or a similar
case. An author is different from a person who forwarded a document.
Contribution is a reason to ask. It does not show authority, ownership,
availability or wider expertise. A display name alone does not identify a
person across systems.

When outreach would resolve a clear gap, propose:

- the recipient and the channel;
- why their contribution is relevant;
- the question and the context you would send.

Send only context that the recipient's audience permits.

## Contact

After approval, send through a host tool if one exists and the recipient is
resolved; otherwise give a draft. If the user declines, leave the gap open.
Before a repeat after an uncertain send, check the channel. A follow-up or
reply monitoring needs its own approval.

## Bring the answer back

Check whether the answer resolves the question. Keep its qualifications, and
keep the person's advice apart from a decision they can make. Apply it to the
task. When you save it, cite the conversation and set `supplier` to the person
who answered. When it answers a `gap` memory, write it as a new version of that
memory.
